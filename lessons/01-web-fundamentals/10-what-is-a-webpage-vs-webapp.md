# What is a Webpage vs a Web App?

> ⏱ 2 min read · 🟢 Beginner

## One Line Answer
A webpage displays information. A web app lets you do things — it responds, remembers, and behaves like software.

## Real World Analogy
A **webpage** is like a printed poster — you read it, but it doesn't react to you.
A **web app** is like an ATM — it responds to your inputs, processes them, and gives back personalised results.

## Live Examples

| Type | Website | Why |
|------|---------|-----|
| Webpage | **https://en.wikipedia.org** | You read it. It doesn't change based on your actions. |
| Web App | **https://www.figma.com** | You design, collaborate, save — it reacts to everything you do. |
| Web App | **https://chat.openai.com** | You type, it responds, it remembers your conversation. |
| Webpage | A restaurant menu online | Static information, nothing to interact with. |

## Key Differences

| Feature | Webpage | Web App |
|---------|---------|---------|
| Updates content | No (manual) | Yes (real time) |
| Needs a backend | Usually not | Almost always |
| Saves your data | No | Yes |
| Responds to you | Barely | Constantly |
| Requires login | Rarely | Often |

## The Grey Zone
Most things today are in between. A blog is mostly a webpage but has comments (app-like). Google Docs is fully a web app that looks like a document.

## How It Shows Up in Our App
Our chat app is a **web app**:
- It remembers your chats
- It sends and receives messages in real time
- The page updates without reloading
- It connects to an AI backend
- Every user action triggers something

## What to Tell AI When You Need It
> "Build this as a web app, not just a static page. It needs to remember state, connect to a backend, and update in real time without page refreshes."

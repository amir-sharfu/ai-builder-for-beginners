# How to Contribute to This Repo

## Why Contribute?
This repo was written for people without a coding background — by someone who experienced the same confusion. The best contributions come from people who:
- Just finished a lesson and found a better analogy
- Got stuck on something not covered here
- Found a broken link or outdated information
- Translated something into their native language

You don't need to know how to code to contribute. You need to have been confused by something and figured it out.

---

## The Easiest Contribution: Fix Something

Found a typo? Confusing sentence? Broken link? Wrong information?

1. Click the file on GitHub
2. Click the pencil (Edit) icon in the top right
3. Make your change
4. Click "Commit changes"
5. Add a short description of what you fixed
6. Submit

GitHub handles everything else. No terminal needed.

---

## Adding a New Lesson

The best new lessons come from real questions. If you got stuck on something and figured it out, that experience is a lesson.

**Lesson template:**
```markdown
# What is [concept]?

## One Line Answer
Plain English, no jargon.

## Real World Analogy
Compare to something familiar.

## Live Example
A real website or URL to visit.

## How It Shows Up in Our App
Where exactly this is relevant.

## What Breaks Without It
Why it matters.

## What to Tell AI When You Need It
An exact prompt.

---
*Previous: [Previous Lesson](xx-previous.md) · Next: [Next Lesson](xx-next.md)*
```

---

## Improving Existing Lessons

If an analogy didn't click for you, suggest a better one. If a live example went offline, find a replacement. If an explanation is technically correct but confusing — rewrite it until it isn't.

The test for a good explanation: **could you explain it to someone who knows nothing, in under 60 seconds?**

---

## Opening an Issue

Not ready to write but found a problem or gap? Open an issue on GitHub:
1. Go to the repo on GitHub
2. Click "Issues" tab
3. Click "New Issue"
4. Describe: what's missing, what's wrong, or what confused you

That's it. Someone will respond.

---

## What Makes a Good Contribution

**Good:**
- Fixing something that's wrong
- Adding an analogy that clicked for you
- A lesson about something genuinely confusing that isn't covered
- A better live example for an existing lesson

**Not as useful:**
- Rewriting lessons to be more technical
- Adding advanced concepts aimed at experienced developers
- Changing voice/tone without improving clarity

The audience is always the same: someone with no coding background who wants to build with AI.
